# 用户指定的默认阅读 Prompt

本地更新：2026-10-26。以下保留用户指定的任务要求，作为默认 DEEP READ 的内容与写作规范；来源核验、发表时背景、离线交付和质量检查继续按 `SKILL.md` 执行。用户当次明确要求缩短或调整范围时，遵循当次要求。

你的任务是：清晰、易懂、深入、详细的总结这篇论文（读取PDF、搜索arxiv等各种信息源获取论文）。

你的总结需要条理清晰的包含下面环节，**并输出包含丰富可视化和交互的html**：
1. 论文提出并解决的研究问题是什么（适当搜索调研和补充背景）？为什么这个问题是重要的？解决这个问题能带来哪些价值？
2. 这个问题之前被解决了吗？之前的研究为什么存在不足？
3. 在正式讲方法之前，先重建作者可能的思考路径。这个部分不要使用论文自己的贡献作为前提，只使用论文之前已有的背景、失败模式、经验观察和相关工作。思考和模拟作者本人的思路和受到的inspiration以及intuition，思考和引导我理解为什么作者可以基于已有知识想到这篇论文的idea
4. 这篇论文提出方法的Intuition是什么？易懂清晰concise的告诉我这篇论文核心idea的本质。
5. 这篇论文的具体方法是什么？结合一个真实的例子讲解：输入、处理、输出完整的pipeline。分点说明，清晰易懂。
6. 这篇论文的核心数学推导过程是什么（一步步从0让我从理论视角理解方法）？如果有，请给我补充理论背景（我的数学比较差），告诉我理论的基础和intuition；如果没有，可以说明并跳过这一点。所有数学公式使用准确的markdown语法确保渲染成功。
7. 这篇论文是如何设计实验来验证提出的方法和claim的？按照下面格式总结：提出了什么问题->设计了什么实验验证这个问题->问题的答案是什么。不需要很多数据细节，只需要核心思路
8. 总结这篇论文的take aways
9. 这篇论文最脆弱的假设是什么？
10. 如果我有1周时间，能做一个最小复现实验验证它的哪一点？
11. 如果我反对它，我会怎么设计反例？
12. 调用搜索工具，调研这篇论文的后续研究，是否有进一步的扩展或者反驳，以及新的认知？
13. 调研、思考、基于你的信息提出一个follow up的idea，要novel，不是增量研究，是从方法缺陷Limitation和需求出发思考可能的新的有价值的研究

要求：
* 风格参考Andrej Karpathy和Kaiming He，要求有真人的语感
* 使用详细的、准确的claim，每句话都要有信息量，避免大空话和泛泛而谈
* 使用流畅的文本，避免滥用破折号、引号，保持输出内容清洁流畅，易读性高
* 使用真人逻辑，避免使用[不是...而是]这种AI的低信息量结构
* 请严格区分四类信息：论文原文明确声称的内容、相关文献中的已有结论、基于证据的合理推断、仍然不确定的猜测。不要把推断写成事实。
* 把论文核心的可视化更易懂的抽取总结到你输出的html中，方便我直接理解

## 补充要求：突出关键方法与新颖设计 · 2026-10-26

保留以上13项结构，重点增强第4–7项：**清楚、醒目地凸显论文中重要的新引入方法、实质改动，以及值得理解的借鉴/适配方法。** 不只概括最高层idea，也不要漏掉正文或附录中会改变计算、信息流或训练/推理方式的具体设计。

- 方法部分先简要说明“此前怎么做 → 本文改了什么 → 希望解决哪个瓶颈”，再在实际pipeline对应位置展开。不能用本文最终方案反过来充当第3项思路重建的前提。
- 对选出的关键机制设置**明确的中文小标题**，保留英文原名，并保留有解释价值的数量与设置，例如“64个可学习虚拟行（thinking rows）”。不能只在总览卡片、术语列表或一段架构概述里顺带提及，也不能把必要解释藏在折叠框中。
- 逐项讲清：**是什么、相对前作改变了什么、来源与原创性归属、为何采用、放在流程哪里、输入/内部状态/输出怎样变化、何时学习或使用、代价与限制、有什么实验证据**。若某项未披露实现或没有独立消融，明确说明，不能用整体提升替它证明独立贡献。
- 在方法图或交互中显式标出这些机制、所处位置与关键连接。图文必须解释同一信息流；视觉高亮不能代替正文说明，也不能凭空补出未披露的mask、标签或实现细节。
- 严格区分“本文提出或实质修改”“借鉴已有方法并适配”“直接沿用”“归因未明”。**本文采用，不等于本文原创；对当前系统新加入，不等于在整个领域首次提出。** 原创性判断与原文/文献/推断/猜测四类信息仍须同时保持清楚。
- 根据对方法理解的重要性选择展开对象，不为每个普通超参数单设章节。交付前回查原文方法、图注、附录与消融：读者是否能发现并解释这些关键设计，而不只是确认文档里出现过其名字？
